# Спільні витрати — Міша & Женя

Односторінковий (SPA) веб-додаток для ведення спільної історії покупок
двох людей. Додаток лише зберігає список транзакцій і показує суму витрат
кожного учасника — **без розрахунку боргів**.

Стек: чистий **HTML / CSS / JavaScript** (без фреймворків, без Node.js,
без бекенду) + **Supabase** як база даних. Готово до розміщення на
**GitHub Pages**.

---

## Структура проєкту

```
index.html     — розмітка сторінки
style.css      — стилі (CSS variables, адаптивність)
config.js      — налаштування Supabase (URL і anon key)
app.js         — вся логіка: запити до Supabase, рендер, форми
schema.sql     — SQL для створення таблиці в Supabase
README.md      — цей файл
```

---

## 1. Створення проєкту Supabase

1. Зареєструйтесь / увійдіть на [supabase.com](https://supabase.com).
2. Натисніть **New Project**.
3. Вкажіть назву проєкту (наприклад, `shared-expenses`), пароль до бази
   даних та регіон (найближчий до вас). Натисніть **Create new project**.
4. Зачекайте 1–2 хвилини, поки Supabase підготує проєкт.

## 2. Створення таблиці `transactions`

1. У боковому меню проєкту відкрийте **SQL Editor**.
2. Натисніть **New query**.
3. Скопіюйте весь вміст файлу [`schema.sql`](./schema.sql) із цього
   проєкту та вставте в редактор.
4. Натисніть **Run**.

Це створить таблицю `transactions` з полями:

| Поле          | Тип         | Опис                                  |
|---------------|-------------|----------------------------------------|
| `id`          | uuid        | Первинний ключ, генерується автоматично |
| `payer`       | text        | `"Міша"` або `"Женя"`                  |
| `amount`      | numeric     | Сума покупки (PLN)                     |
| `description` | text        | Опис покупки (необов'язково)           |
| `created_at`  | timestamptz | Дата створення, ставиться автоматично  |

Скрипт також вмикає **Row Level Security** з політиками, що дозволяють
читання та запис усім, хто має публічний (anon) ключ проєкту — це потрібно,
бо в додатку немає окремої авторизації користувачів.

## 3. Отримання URL та Anon Key

1. У боковому меню відкрийте **Project Settings → API**.
2. Знайдіть розділ **Project API keys / Data API**:
   - **Project URL** — це значення для `SUPABASE_URL`.
   - **anon / public key** — це значення для `SUPABASE_ANON_KEY`.

   ⚠️ Використовуйте саме **anon (public)** ключ. Ніколи не використовуйте
   `service_role` ключ у клієнтському коді — він дає повний доступ до бази
   даних і не повинен потрапляти у браузер чи публічний репозиторій.

## 4. Налаштування `config.js`

Відкрийте файл `config.js` у проєкті та замініть плейсхолдери на свої
значення:

```javascript
const SUPABASE_URL = "https://your-project-ref.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...";
```

Збережіть файл. Додаток одразу почне працювати з вашою базою даних.

---

## 5. Розміщення на GitHub Pages

1. Створіть новий репозиторій на GitHub (наприклад, `shared-expenses`).
2. Завантажте туди всі файли проєкту (`index.html`, `style.css`,
   `config.js` — уже з вашими ключами, `app.js`), наприклад:

   ```bash
   git init
   git add .
   git commit -m "Спільні витрати: перший реліз"
   git branch -M main
   git remote add origin https://github.com/USERNAME/shared-expenses.git
   git push -u origin main
   ```

3. У репозиторії відкрийте **Settings → Pages**.
4. У розділі **Build and deployment** оберіть:
   - **Source**: `Deploy from a branch`
   - **Branch**: `main`, папка `/ (root)`
5. Натисніть **Save**.
6. Через 1–2 хвилини сайт буде доступний за адресою:

   ```
   https://USERNAME.github.io/shared-expenses/
   ```

Додаткових кроків збірки не потрібно — це звичайні статичні файли.

## Використання

- **Додати транзакцію** — кнопка «+ Додати» відкриває форму: оберіть, хто
  заплатив, введіть суму (PLN) та, за бажанням, опис. Дата запису
  проставляється автоматично.
- **Редагувати** — кнопка ✏️ на картці транзакції.
- **Видалити** — кнопка 🗑️ на картці, з підтвердженням.
- Угорі сторінки завжди видно суму витрат Міші, Жені та загальну суму —
  це лише суми покупок, без розрахунку "хто кому винен".

---

## Примітки з безпеки

Оскільки в додатку немає авторизації, будь-хто з посиланням на anon key
(видимим у вихідному коді сторінки) технічно може читати й змінювати дані
через Supabase API. Для приватного застосунку "для двох", яким ви не
ділитесь публічно, це прийнятний компроміс. Якщо потрібен вищий рівень
захисту — додайте Supabase Auth (наприклад, вхід за email-посиланням) і
звужте політики RLS у `schema.sql` до перевірки конкретного користувача.
